# Модуль «Облік авто СТО БАЗА» (етапи 1–5)

Замінює Google-таблицю `STO_BAZA_Oblik`. Призначений для вбудовування в «Штаб» (Next.js 15 static export + Supabase).

## Що вже є
- `supabase/base_000_standalone_stubs.sql` — ТІЛЬКИ для окремої розробки: імітація `auth.uid()`, `is_member()`, `is_head()`.
- `supabase/base_001_schema.sql` — таблиці `base_*`, довідники значень, журнал змін, тригери.
- `supabase/base_002_views.sql` — тривалість робіт, фактичне середнє, борги по особі, витрати по авто, дашборд.
- `src/import/parse.ts`, `src/import/sync.ts`, `scripts/import-xlsx.ts` — імпорт з xlsx (етап 2).
- `tests/` — тести розрахунків, цілісності й імпорту на Postgres (PGlite).

## Запуск тестів
```
npm install
npm test
```
Потрібен лише Node 20+. Docker і Supabase не потрібні.

## Правила розрахунків (звірено з таблицею v28)
- **Тривалість роботи** = `finished_on − started_on` у днях, лише для статусу «Завершено» з обома датами.
- **Фактичне середнє** по номенклатурі = середня тривалість завершених робіт, округлено до 0,1 дня. У таблиці зіставлення йде за назвою роботи, тут за `nomenclature_id`. Результати збігаються, якщо опис роботи дорівнює стандартній назві.
- **Борг по особі** = сума витрат зі статусом «Очікує оплати» за полем `person_dejure` (колонка «ПІБ_особи ДеЮрЕ»). Рядки без особи не враховуються.

## Рішення Олега (18.11.2026)
- `base_parts.cost_total` — ціна за всю позицію (усі штуки разом; у даних 4 шт. × 4900 = 19600).
- Керівник «Бази» — Олег (за потреби ще Андрій): список `base_heads`, функція `base_is_head()`.
- Куди йдуть невизначені й спільні платежі, вирішує Олег — сторінка «Платежі без авто» (`/base/payments/`).
- Роботи й запчастини додає Олег: «Швидке введення» або бот («021 робота Заміна ГРМ», «021 запчастина Ремінь ГРМ 2 шт 4900 грн» → кнопка «Додати»).

## Відомі припущення
- `ID_роботи` у таблиці — це ID номенклатури, він повторюється по авто, тому власний ключ роботи сурогатний.
- `base_ref_models` має 8 полів за карткою «Довідник_авто»; структуру довідного аркуша потрібно звірити при імпорті.

## Імпорт з xlsx
```
DATABASE_URL=postgres://... npm run import -- --file таблиця.xlsx            # лише план, нічого не пишеться
DATABASE_URL=postgres://... npm run import -- --file таблиця.xlsx --apply    # записати НОВІ рядки
```
Правила:
- Читаємо лише колонки введення за назвами заголовків, формульні колонки ігноруємо.
- `--apply` лише додає нові рядки в одній транзакції. Існуючі рядки ніколи не перезаписуються: відмінності показуються як «розбіжності».
- Рядки з недопустимими статусами/джерелами, зламаними датами чи неіснуючим авто відхиляються з причиною, решта імпортується.
- Рядки без природного ключа (роботи, запчастини, фінанси, документи) ідентифікуються відбитком + лічильником повторів, тому повторний імпорт нічого не дублює. Якщо рядок змінили у файлі, він з'явиться як новий, а старий у списку «є в базі, немає у файлі»; нічого не видаляється.
- Дані поза межами таблиці (наприклад, текст у стовпці 23) не імпортуються, але видно в попередженнях.
- Старі Drive-посилання зберігаються в `legacy_links` до міграції файлів у Storage.
- Фінансові рядки без ID авто (спільні платежі, оренда СТО) імпортуються як `scope = 'unassigned'` і потребують віднесення вручну.
- Файл xlsx не комітити (у `.gitignore`).

Скрипт з `DATABASE_URL` перевірено лише на PGlite (Postgres у WASM); на живому Supabase не запускався.

## Telegram-бот і фото
Бот (`supabase/functions/_shared/base-bot/`): зведення й нагадування керівникам, запити команди, статус кнопками, фото → папка авто на Google Drive (питає «До якого авто?», підпис «021 до» — одне натискання).
